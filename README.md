## 📌 Overview

**OnionGrade AI** is an AI-assisted onion quality assessment and grading system designed to analyze onion batches from images and provide a structured digital quality assessment.

The system combines **Google Gemini Vision**, deterministic Python grading rules, image preprocessing, validation, optional NIR/SWIR screening, report generation, batch analysis, scan history, and multiple export formats into a single workflow.

The core design principle is:

> **AI perceives, Python decides.**

Gemini Vision is responsible for visual perception and observation, while the final grading and percentage calculations are handled by deterministic Python rules.

---

## 🎯 Objectives

* Analyze onion batches from uploaded images.
* Identify visual characteristics such as size, colour, sprouting, and visible defects.
* Classify individual onions into **Grade A, URS, or Defect**.
* Calculate batch-level grading percentages.
* Provide confidence-based review information.
* Support multiple images in a single batch analysis.
* Provide optional RGB-proxy and real NIR/SWIR inspection.
* Maintain local scan history.
* Generate structured reports.
* Export results in CSV, JSON, PDF, and XLSX formats.
* Provide demo/offline operation when Gemini API access is unavailable.
* Maintain a clear separation between AI perception and deterministic grading.

# ⭐ Features

## 1. AI-Based Onion Perception

Gemini Vision analyzes the uploaded image and provides visual observations including:

* Size
* Colour
* Sprouting
* Visible defects
* Other supported visual characteristics

The AI output is converted into a structured response before entering the grading pipeline.

---

## 2. Deterministic Python Grading

The final grade is **not directly generated by Gemini**.

After AI perception and validation, the system applies deterministic Python rules.

The classification categories are:

| Category       | Description                                                                 |
| -------------- | --------------------------------------------------------------------------- |
| 🟢 **Grade A** | Onion satisfying the defined accepted quality conditions                    |
| 🟡 **URS**     | Onion falling into the defined usable/review category                       |
| 🔴 **Defect**  | Onion showing characteristics that place it outside the accepted categories |

The grading logic is implemented in:

```text
backend/app/grading_rules.py
```

---

## 3. Batch Percentage Calculation

The system calculates the percentage of each grading category.

```text
Grade A % = (Grade A onions / Total onions) × 100

URS % = (URS onions / Total onions) × 100

Defect % = (Defect onions / Total onions) × 100
```

The percentages are displayed on the dashboard and included in generated reports and exports.

---

## 4. SQLite Scan History

Every completed analysis can be stored locally in SQLite.

### Capabilities

* Automatically saves analysis results.
* Stores previous scans.
* Lists previous scans on the dashboard.
* Reloads previous scan results without calling Gemini again.
* Allows individual scans to be deleted.
* Database path can be configured through:

```text
ONIONGRADE_DB_PATH
```

Default database:

```text
data/scans.db
```

---

## 5. Per-Onion Crop Thumbnails

The system can generate individual onion crops from the original image using detected bounding boxes.

The dashboard can display:

* Onion thumbnail
* Onion ID
* Grade
* Confidence
* Review status

The main image's bounding-box overlay is also preserved.

---

## 6. Image Preprocessing

Before sending an image for AI analysis, the system performs preprocessing.

### Processing includes:

* EXIF orientation correction.
* Automatic image rotation.
* Resize to a maximum 1024px longest side.
* Aspect ratio preservation.
* JPEG re-encoding at quality 85.
* Metadata stripping.
* Logging of original and processed dimensions/size.

The original image is preserved for UI display and supported analysis workflows.

---

## 7. AGMARK Diameter-Based Size Grading

The grading system supports physical diameter-based size grading when proper image calibration is available.

Calibration can be supplied using:

```text
pixels_per_mm
```

from a known reference object in the image.

### Important behavior

* With calibration → physical diameter can be calculated.
* Without calibration → the system falls back to the existing size-class method.
* The system does **not fabricate physical measurements** when calibration is unavailable.

The diameter calculation is implemented through:

```text
compute_diameter_mm()
```

in:

```text
grading_rules.py
```

---

## 8. Confidence Threshold

A confidence threshold can be selected through the Streamlit sidebar.

### Range

```text
0.50 → 0.90
```

### Default

```text
0.70
```

Detections are categorized as:

```text
Confidence ≥ threshold
        ↓
Accepted
```

```text
Confidence < threshold
        ↓
Low Confidence
```

Low-confidence detections remain visible and are **not silently removed**.

The status is shown through the:

```text
review_status
```

field.

The selected threshold is also passed to the backend.

---

## 9. Multi-Image Batch Analysis

Multiple images can be uploaded for a single batch analysis.

Each image is:

1. Analyzed separately.
2. Given its source image label.
3. Added to the combined batch result.

The final batch combines:

* Grade A counts
* URS counts
* Defect counts
* Percentages

Example source labels:

```text
image1.jpg
image2.jpg
image3.jpg
```

Multi-image runs receive an automatically prefixed batch ID:

```text
MULTI-Nimg
```

## 10. Real NIR/SWIR Input

The system supports an optional real NIR/SWIR input workflow.

Endpoint:

```text
POST /analyze/nir
```

It accepts:

```text
rgb_file
nir_file (optional)
```

### Real NIR mode

When an NIR file is supplied:

```text
nir_input_mode = real_nir
```

The supplied NIR image is used for the NIR screening pipeline.

### RGB-proxy mode

When no NIR image is supplied:

```text
nir_input_mode = rgb_proxy
```

The existing RGB-proxy method is used.

The system explicitly distinguishes the two modes and does **not** claim that RGB-proxy analysis is equivalent to real NIR.

The Streamlit interface also provides an optional second uploader when NIR inspection mode is selected.

Result badges indicate:

```text
📡 Real NIR/SWIR
```

or

```text
🔬 RGB-proxy NIR (simulated)
```

## 15. Multi-Model Gemini Fallback

The Vision layer supports a configurable fallback chain of Gemini models.

Environment variable:

```text
GEMINI_VISION_MODELS
```

Models can be provided as a comma-separated list.

If a model cannot complete the request because of a transient failure or availability issue, the system can continue through the configured fallback chain.

This allows the application to remain more resilient to individual model availability or quota limitations.

* LangChain

* Batch grading information

The report generation layer is separate from the deterministic grading engine.

If live report generation is unavailable, the system can use the available template-based fallback.

# 🤖 AI Architecture

The project intentionally separates **AI perception** from **decision logic**.

```text
              Onion Image
                   ↓
            Gemini Vision
                   ↓
          Visual Observations
                   ↓
          Pydantic Validation
                   ↓
       Deterministic Python Rules
                   ↓
             Final Grade
                   ↓
       Percentages + Assessment
```

### Why this architecture?

Gemini is used for visual understanding, while Python handles the actual grading rules.

Therefore:

> **The AI observes. The rule engine decides.**

This makes the grading process more transparent, reproducible, and easier to audit.

# 📴 Demo / Offline Mode

OnionGrade AI can operate without a Gemini API key.

If:

```text
GOOGLE_API_KEY
```

is not configured, the backend runs in **DEMO_MODE**.

The system supports:

### Synthetic Demo

```text
DEMO_DATA_MODE=synthetic
```

A fixed demonstration onion batch is used.

### Offline Computer Vision

```text
DEMO_DATA_MODE=cv
```

OpenCV-based detection can be performed on the uploaded image.

The application can still demonstrate:

* Grading
* Calculations
* History
* Thumbnails
* Reports
* Exports
* Dashboard functionality

without requiring a live Gemini request.

# ⚠️ Known Limitations

## 1. AGMARK Diameter Calibration

Physical diameter measurement requires a known reference object, such as a ruler, and valid `pixels_per_mm` calibration.

Without calibration, the system falls back to visual size classification:

```text
Small / Medium / Large
```

The system does not fabricate physical measurements.

---

## 2. Real NIR/SWIR Analysis

Although the system accepts a real NIR image through:

```text
/analyze/nir
```

the current analysis metrics were originally designed around RGB-image characteristics.

A true NIR sensor produces different spectral information.

Therefore, real NIR results should be treated as **experimental until validated against appropriate physical reference measurements and field data**.

---

## 3. Internal Defects

Normal RGB camera inspection cannot reliably identify all internal defects, including:

* Hollow heart
* Double bulb
* Sub-surface rot

OnionGrade AI is therefore intended as a **digital pre-check**, not a replacement for official AGMARK certification or physical inspection.

---

## 4. Demo Mode Accuracy

The synthetic demo batch is fixed for demonstration purposes.

OpenCV CV mode can operate on actual images but provides a rough computer-vision estimate compared with Gemini's visual understanding.

Demo results should not be interpreted as field-validated grading results.

---

## 5. Image Quality

Performance can be affected by:

* Poor lighting
* Low image resolution
* Onion overlap
* Occlusion
* Camera angle
* Background conditions

Good image capture is important for reliable visual analysis.

---

## 6. History Image Recovery

SQLite history stores analysis results and per-onion grades.

The original uploaded image bytes are not stored in the database to avoid large blob storage.

Therefore, when a historical scan is reloaded:

* Analysis results are available.
* Per-onion grades are available.
* Original image bytes are not restored.
* The original marked-image overlay is unavailable.
